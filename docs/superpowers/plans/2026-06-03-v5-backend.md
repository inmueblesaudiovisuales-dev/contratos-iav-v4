# V5 Backend — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the backend to support the V5 "trabajos-first" model: unified token between trabajo and contrato, new status set (Nuevo → Cancelado), inmobiliaria field on clientes, and expanded equipo.js with cliente/trabajo/actividades data.

**Architecture:** Every trabajo gets a UUID token at creation. When formalized into a contrato, the contrato uses that same token as its PK. Status lives on `trabajos.estatus` (full lifecycle) and is synced to `contratos.estatus` for backward compat. equipo.js resolves data by token, returning cliente + trabajo + actividades + contrato (if exists) + propiedades.

**Tech Stack:** Cloudflare Workers, D1 (SQLite), Wrangler CLI, Google Apps Script adapter

**Spec:** `docs/superpowers/specs/2026-06-03-v5-trabajos-redesign.md`

**IMPORTANT context for all tasks:**
- Working dir for all commands: `worker/`
- Deploy: `git add ... && git commit -m "..." && git push origin main`
- D1 migrations: `npx wrangler d1 migrations apply contratos-iav-v4 --remote`
- All backend files live in `worker/src/routes/`
- `callAdapter(ctx, env, action, payload)` = fire-and-forget to Google Apps Script
- `callAdapterSync(env, action, payload)` = awaited call that returns JSON response
- Both are exported from `worker/src/google.js`
- D1 does NOT enforce foreign keys — cascades must be done manually in code
